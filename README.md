## 🧠 How I think about engineering

I optimize for **leverage**, not lines of code.

### 01 · Understand the problem
Before choosing a library or writing a component, I identify the user, the business rule, and the failure modes.

### 02 · Design the system
I prefer clear boundaries, reusable primitives, predictable data flow, and architecture that can survive the next feature.

### 03 · Build for the real world
Loading states, validation, permissions, empty states, errors, accessibility, responsive behavior, and edge cases are part of the feature.

### 04 · Ship and improve
A solution is not finished because it works on localhost. It is finished when users can depend on it.
